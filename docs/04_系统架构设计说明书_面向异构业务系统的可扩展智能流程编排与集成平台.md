# 04_系统架构设计说明书

## 架构定位

系统采用前后端分离、后端 Maven 多模块、业务层接口与实现分离、MyBatis XML 持久层的架构。当前不拆微服务，优先保证模块边界清晰、代码可继续开发。

## 总体结构

```text
frontend
  -> REST API
backend-controller
  -> service interface
backend-biz service.impl
  -> mapper interface
mapper_autoprocess XML
  -> MySQL
```

## 后端模块

| 模块 | 职责 |
|---|---|
| autoprocess-common | 统一响应、异常、工具。 |
| autoprocess-entity | 实体、枚举、流程节点模型。 |
| autoprocess-biz | Service 接口、ServiceImpl、Mapper、XML、流程引擎占位。 |
| autoprocess-controller | REST Controller、DTO、异常处理。 |
| autoprocess-server | 启动类、配置文件、数据库迁移脚本。 |

## 前端模块

| 模块 | 职责 |
|---|---|
| api | 封装后端接口请求。 |
| views | 页面入口：总览、连接器、流程、实例、审批。 |
| components/workflow | 流程画布组件。 |
| router | 路由配置。 |
| settings | 菜单配置。 |
| types | 前端业务类型。 |

## 数据流

1. 前端通过 Controller 调用后端接口。
2. Controller 只依赖 Service 接口。
3. ServiceImpl 完成业务编排和事务控制。
4. Mapper 接口对应 XML SQL。
5. 数据写入 MySQL。

## 扩展原则

- 新增外部系统能力：增加连接器和连接器动作，不改平台核心模型。
- 新增节点类型：增加 NodeExecutor 实现和前端节点配置，不改流程定义主结构。
- 新增业务场景：通过流程模板和连接器配置完成，不写死进数据库主模型。

## 当前架构阶段

当前处于“骨架可编译、业务待实现”阶段。架构边界已经确定，后续开发应在现有目录内补充代码，不再新增无关模块或把所有代码堆回单个 `src`。
