# 03_需求分析说明书

## 需求定位

本系统的业务方向是“跨系统流程编排与集成”，不是“订单管理”“ERP 管理”或某个单一行业系统。需求围绕平台能力展开。

## 用户角色

| 角色 | 主要操作 |
|---|---|
| 系统管理员 | 用户、连接器、代理、系统配置管理。 |
| 流程设计人员 | 创建流程、配置节点、发布流程。 |
| 审批人员 | 查看审批任务，执行通过或拒绝。 |
| 运维/查看人员 | 查看流程实例、节点日志、事件记录和错误信息。 |
| 外部系统 | 通过 API、Webhook 或代理与平台交互。 |

## 核心功能需求

| 编号 | 功能 | 说明 |
|---|---|---|
| FR-01 | 用户与角色基础 | 支撑登录、角色识别、审批人扩展。 |
| FR-02 | 连接器管理 | 管理外部系统基础信息、认证方式、启用状态。 |
| FR-03 | 连接器动作管理 | 配置外部系统可调用动作、输入 Schema、输出 Schema。 |
| FR-04 | 流程定义管理 | 创建、保存、发布、停用流程定义。 |
| FR-05 | 流程设计器 | 编辑节点、连线、节点配置并保存 JSON。 |
| FR-06 | 事件触发 | 支持手动触发和 Webhook 事件接入。 |
| FR-07 | 流程实例 | 保存运行上下文、当前节点、状态和错误信息。 |
| FR-08 | 节点日志 | 记录节点输入、输出、状态和错误原因。 |
| FR-09 | 审批任务 | 支持审批任务创建、查询、通过、拒绝。 |
| FR-10 | Edge Agent 预留 | 为后续企业内网系统访问预留代理表和模块。 |
| FR-11 | AI 辅助预留 | 为异常解释、字段建议等能力预留日志和模块。 |

## 当前工程承接

当前工程已搭好基础结构，但业务实现仍是占位：

- 后端已有多模块、实体、枚举、Mapper、XML、Service 接口、ServiceImpl 占位、Controller。
- 前端已有基础页面、路由、菜单、接口封装和业务类型。
- 数据库脚本已有平台核心表。

## 后续开发重点

后续需求实现顺序应为：连接器基础 CRUD -> 动作配置 -> 流程定义保存 -> 流程发布校验 -> 事件触发 -> 流程实例创建 -> 节点日志 -> 审批任务 -> 流程引擎执行。
